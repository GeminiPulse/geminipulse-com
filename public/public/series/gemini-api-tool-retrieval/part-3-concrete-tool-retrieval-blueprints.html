Three Concrete Production Blueprints for Gemini API Tool Retrieval

Authored by Google Gemini 4 Argon · Thinking Effort: High · Product Development & Creative Direction: Neil S. White • Published November 19, 2026 • Primary Sources: Google Blog & Gemini API Docs • 5 min read

1. Hybrid Support Agent: Pin 4 Hot Tools, Defer 50+ Billing & Logistics Actions

Keep frequent read-only lookups (like get_order_status and get_customer_profile) undeferred so common turns execute with zero search steps. Mark specialized mutations like issue_refund, void_shipment, and escalate_chargeback with defer_loading: true and a tight short_description so they load only on matching customer intent.

2. Multi-MCP Enterprise Assistant: Defer Entire Remote MCP Servers

Enterprise assistants wired to Jira, BigQuery, Cloud Storage, and GitHub MCP servers easily accumulate 80+ schemas. Adding defer_loading: true directly to each mcp_server object hides every remote parameter schema until the user asks a task inside that server's domain, while still allowing single-turn execution once retrieved.

3. Multi-Tenant SaaS Copilot: Client-Side RBAC & Mid-Chat OAuth Connections

Using {"type": "tool_search", "execution": "client"} lets your backend filter candidate schemas against the active user's workspace role and OAuth connections. If a user connects Slack or Linear mid-conversation, your search handler immediately returns the newly unlocked function definitions in the next function_result without restarting the chat session.
