What Changed With Tool Retrieval in the Gemini API: On-Demand Schemas for Large Agent Libraries

Authored by Google Gemini 4 Argon · Thinking Effort: High · Product Development & Creative Direction: Neil S. White • Published November 19, 2026 • Primary Sources: Google Blog: Introducing Tool Retrieval, Gemini API Tool Retrieval Docs & Changelog • 6 min read

Release Summary: November 19, 2026 (18:00 UTC)

Google launched Tool Retrieval in preview inside the Gemini Interactions API (v1beta) across Gemini 3.6 and all Gemini 4 models. By adding {"type": "tool_search"} and setting defer_loading: true on long-tail functions or remote mcp_server declarations—or wiring execution: "client" to a private registry—agents avoid paying per-turn input token rent on unused JSON parameter schemas while keeping tool-selection accuracy sharp.

1. The Two-Front Scaling Problem Static Tool Declarations Created

Before November 19, 2026, calling functions or remote MCP servers on the Gemini API required sending every complete JSON Schema inside the initial prompt context on every single turn. Once an enterprise assistant connected to 30 internal APIs and three MCP servers, two regressions hit simultaneously:

  • Context Token Bloat: A few dozen nested parameter definitions routinely consume tens of thousands of input tokens on every turn—even when the user simply asks a status question that uses zero tools or one function.
  • Routing Accuracy Decay: Pushing dozens of dense, overlapping parameter schemas into the prompt degrades function-selection precision as the candidate list expands.

2. Static Loading vs. Server-Side vs. Client-Side Retrieval

Capability Static Tool Loading Server-Side Retrieval (Default) Client-Side Retrieval (execution: "client")
How Schemas Reach Gemini All schemas sent on every request Gemini loads deferred schemas on demand inside one API call Your application searches and returns schemas in function_result
Retrieval Code Needed None None (declarative tool_search + defer_loading) Custom search, ranking, or per-user RBAC filter
Upfront Declaration Required Required (name + description / short_description) Not required (can inject newly connected tools mid-chat)
Remote MCP Support Yes Yes (defer_loading: true defers all server tools) Not applicable
Extra Round Trips None None One extra round trip per search invocation
Ideal Use Case Fewer than ~20 stable tools Large fixed tool libraries & multi-MCP assistants Proprietary vector registries, namespaces & strict per-user RBAC

3. Scope, Pricing & Compatibility Boundaries

  • Interactions API (v1beta) Exclusive: Tool Retrieval requires the Interactions API on v1beta and works with Gemini 3.6 and later models, including all Gemini 4 models (gemini-4-hydrogen, gemini-4-neon, gemini-4-carbon, gemini-4-argon). It is not supported on generateContent.
  • Pricing Structure: Google charges no separate retrieval fee. Enabling tool_search adds a small fixed block of input tokens, and each schema loaded during a conversation is billed as standard input tokens for subsequent turns in that session.
