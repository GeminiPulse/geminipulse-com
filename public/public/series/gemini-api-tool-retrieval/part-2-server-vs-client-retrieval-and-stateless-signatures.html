Inside Server & Client Tool Retrieval: Prefix Caching, Step Traces & Stateless Rules

Authored by Google Gemini 4 Argon · Thinking Effort: High · Product Development & Creative Direction: Neil S. White • Published November 19, 2026 • Primary Source: Gemini API Tool Retrieval Docs • 7 min read

1. Single-Call Execution Trace Under Server-Side Retrieval

When you pass {"type": "tool_search"} alongside deferred functions or deferred mcp_server declarations, the model sees only tool names and descriptions (or your compact short_description). Inside one API call, interaction.steps resolves the search and emits the invocation:

  1. tool_search_call (id: "tsc_abc123", arguments: { function_names: ["weather_service:get_weather", "convert_currency"] }, plus opaque signature).
  2. tool_search_result (call_id: "tsc_abc123", full resolved schemas in result, plus opaque signature).
  3. mcp_server_tool_call & mcp_server_tool_result (executed automatically by the API for remote MCP servers) and/or your own function_call step.

Why Prefix Caching Stays Intact

Deferred parameter schemas never mutate the initial prompt prefix. Instead, retrieved schemas append later in the conversation step stream—meaning your cached prompt prefix remains identical across turns and across different tool-loading paths.

2. Four Protocol Invariants That Prevent HTTP 400 Errors

Critical Multi-Turn & Stateless Rules

  • Resend the Full tools Array Every Turn: Even when passing previous_interaction_id, the API does not carry tool declarations across requests. Always resend tool_search, every deferred tool, and every non-deferred tool.
  • Keep tool_search_call & tool_search_result Verbatim When store: false: Never strip, reconstruct, or drop the encrypted signature fields. Missing steps trigger Server side tool call context must be circulated when using deferred loading functions; stripped signatures trigger Tool call part is missing thought_signature.
  • Never Mix defer_loading With execution: "client": Client-side retrieval rejects defer_loading: true with HTTP 400.
  • Require defer_loading: true for short_description: Setting short_description on an undeferred function returns HTTP 400.

3. Client-Side Retrieval Request Contract

{
  "type": "tool_search",
  "execution": "client",
  "name": "search_tool_registry",
  "description": "Search the internal tool registry for functions.",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string" },
      "namespace": { "type": "string" },
      "limit": { "type": "integer" }
    },
    "required": ["query"]
  }
}

Notice that name, description, and parameters are required for execution: "client" and forbidden on server-side {"type": "tool_search"}. Exactly one tool_search tool is allowed per request.
