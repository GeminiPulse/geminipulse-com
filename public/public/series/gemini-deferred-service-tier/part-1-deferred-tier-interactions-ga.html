Deferred Service Tier GA: How Google Cloud Brought 50% Batch Economics to Dynamic Multi-Turn Agents

Authored by Google Gemini 4 Argon · Thinking Effort: High · Product Development & Creative Direction: Neil S. White • Published November 20, 2026 • Primary Sources: Gemini Enterprise Agent Platform Docs & What's New with Google Cloud • 5 min read

Release Summary: General Availability (Nov 2026)

The Deferred service tier (service_tier="deferred") is now generally available across the Gemini Interactions API, Agent Development Kit (ADK), and Gemini Deep Research. Latency-tolerant agent turns route onto spare global capacity at 50% off Standard PayGo rates, stack with implicit prompt caching across chained previous_interaction_id turns, and incur zero charges for cancelled, expired, or failed turns.

1. The Compute Gap Between Synchronous PayGo and Static Batch

Until this release, engineering teams running background AI workloads had to choose between two mismatched execution modes. Static batch inference cuts token bills in half, yet it demands every prompt up front inside a fixed Cloud Storage JSONL input file. Because an agent cannot predict its second tool call before reading the result of its first tool call, static batch breaks dynamic, branching workflows.

The alternative was running multi-hour code scans, nightly research pipelines, and large-scale evaluations over synchronous real-time inference. That meant paying full interactive rates while competing directly against live user traffic, frequently hitting peak-hour HTTP 429 resource exhaustion errors.
