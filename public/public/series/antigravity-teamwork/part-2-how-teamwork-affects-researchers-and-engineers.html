1. Molecular Chemistry Discovery: Solving Nuclear Magnetic Resonance (NMR)

Determining a molecule's 3D chemical structure from experimental 1D/2D Nuclear Magnetic Resonance (NMR) spectra is one of chemistry's most difficult inverse problems. In pharmacology, a single misassigned stereocenter or misplaced bond separates an active life-saving therapeutic from an inactive isomer or a toxic compound.

Single foundation models struggle with NMR interpretation because predicting chemical shifts requires deep physical simulation rather than linguistic pattern-matching. Using /teamwork, Google Research organized 30 specialized agents into a coordinated harness:

  • Candidate Generator Agents: Hypothesize candidate 3D molecular structures consistent with stoichiometry and 2D connectivity.
  • Dedicated Physics-Informed Spectral Simulators: Compute simulated NMR chemical shifts for candidate structures.
  • Falsifier & Metric Auditor Agents: Compare simulated spectra against empirical experimental NMR peaks, scoring candidate likelihood and feeding residual discrepancies back to the generators.

2. Memory-Safe Systems Software: 800k Lines of Rust in Fuchsia & Faster dav1d

The industry consensus has been that automated large-scale language migrations fail because agents take shortcuts—stubbing out awkward dependencies, mocking complex concurrency primitives, or editing unit tests to make a broken port appear green.

Antigravity's /teamwork solved this through the Safe Rust Migration Pattern:

  1. Dependency-Ordered Compilation Scheduling: Modules are scheduled for rewrite strictly after their upstream dependencies compile, linking every leaf against the original, unmodified C++ test harness.
  2. Zircon Microkernel Rewrite: Building on an initial 25% port of Fuchsia's Zircon microkernel, a two-week Argon campaign rewrote the remaining C++ code, adding roughly 800,000 lines of safe Rust that pass all kernel unit tests and successfully boot on bare-metal arm64 hardware.
  3. dav1d AV1 Decoder Port: Ported Google's flagship AV1 video decoder from C++ into ~170,000 lines of Rust with 100% bit-exact parity across the full conformance suite. While initially 4x slower, giving the agent profiling tools and an optimization mandate produced a Rust binary that is 20% to 30% faster than the original C++ and hand-tuned assembly code on both x86_64 and ARM.

⚡ TPU Kernel Acceleration with DuoDiscover Yardsticks

Full hardware evaluations of custom JAX and Pallas TPU kernels take 7 to 32 minutes per run, bottlenecking search. Using the DuoDiscover pattern on Argon, four parallel agents constructed 23-second proxy evaluators ("yardsticks") calibrated via Kendall's rank correlation. DuoDiscover achieved a 4.09x geometric-mean speedup across 17 JAXBench kernels and a 2.99x speedup across 7 hand-optimized vLLM TPU-Inference Pallas kernels for frontier open-weight models.

3. Google Fleet-Scale Production Infrastructure Gains

The truest test of an agentic architecture is whether its optimizations survive production at Google scale. Google Research reported two verified infrastructure deployments:

A. Fleet-Wide Memory Optimization (>1 PiB RAM Saved)

Google deployed a human-in-the-loop Memory Efficiency Monitoring Agent using reusable /teamwork workflows. By systematically identifying memory-saving opportunities across Google's global server fleet, the team eliminated over 1 PiB (petabyte) of RAM using surgical low-level techniques:

  • Struct padding elimination: Reordering struct fields by alignment to eliminate internal compiler padding gaps.
  • Scalar narrowing: Downcasting overly wide 64-bit integer fields to 32-bit or 16-bit primitives where values are proven bounded.
  • Cliff jumping: Eliminating catastrophic buffer reallocation cliffs.
  • Outlining & Tagged Pointers: Compacting cold data pointers and packing status bits into unused virtual memory address bits.

B. Borg Autonomous Scheduling Optimization (-24% TPU Preemptions)

Google's cluster management system, Borg, deployed an agentic workflow for scheduling optimization that shipped 2 production changes, driving a 24% reduction in TPU workload preemption on target hardware clusters while maintaining 100% of workload Service Level Objectives (SLOs) and peak cluster utilization.
