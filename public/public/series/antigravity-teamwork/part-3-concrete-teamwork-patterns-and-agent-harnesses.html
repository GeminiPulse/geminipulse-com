1. The Anatomy of an Antigravity /teamwork Harness

In Google Antigravity, a /teamwork system consists of five specialized roles collaborating over a structured shared board:

Role Recommended Model Primary Responsibility Context Isolation Mode
Coordinator gemini-4-carbon Maintains global state, task decomposition, dependency graph DAGs, and milestone handoffs. Never writes code or proofs directly. Persistent root session
Generator Worker Pool gemini-4-hydrogen High-velocity parallel execution ($1.50/1M input). Generates candidate proof lemmas, Rust modules, or molecular isomers. workspace: "branch" (isolated git worktree)
Dedicated Falsifier Deterministic Tool / Compiler Unbiased automated oracle: Lean 4 proof checker, unmodified test suite, physical simulator, or hardware performance counter. Sandboxed execution runner
Independent Auditor / Critic gemini-4-argon Receives candidate artifacts in clean context. Verifies assumptions, checks for shortcutting or test mutation, and signs verification certificates. Pristine context (no generator history)
Yardstick Proxy Evaluator gemini-3.8-flash Constructs fast 20–30s proxy rankings (calibrated against slow 30-min hardware runs via Kendall's rank correlation). Parallel evaluation sandbox

Antigravity users invoke teamwork workflows directly via natural language or declarative specifications. Below is the configuration pattern used for memory-safe kernel migrations and formal mathematics verification:

# .antigravity/workflows/safe-rewrite-teamwork.yaml
name: "memory-safe-kernel-migration"
description: "Iterative C++ to Safe Rust migration with bit-exact test suite verification"
orchestration:
  coordinator:
    model: "gemini-4-carbon"
    thinking_level: "high"
    instructions: "Maintain strict module dependency DAG. Schedule leaf modules only after upstream deps compile."
  
  worker_pool:
    name: "rust-porter"
    model: "gemini-4-hydrogen"
    thinking_level: "high"
    workspace: "share"
    concurrency: 4
    timeout_minutes: 45

    type: "deterministic"

    model: "gemini-4-argon"
    thinking_level: "xhigh"
    trigger: "on_falsifier_pass"
    checks:
      - "zero_unsafe_blocks"
      - "zero_modified_test_fixtures"
      - "bit_exact_parity_verification"

3. Wiring the Gen AI SDK v3.3.0 for Autonomous Falsifier Loops

Using the official @google/genai v3.3.0 SDK, developers can implement multi-agent verification loops using the Interactions API with native automatic_continuation and deterministic tool calling:

import { GoogleGenAI, Type } from "@google/genai";

const ai = new GoogleGenAI();

// 1. Define the deterministic falsifier tool
const lean4FalsifierTool = {
  name: "verify_lean4_theorem",
  description: "Submits formal Lean 4 proof script to the official compiler kernel.",
  parameters: {
    type: Type.OBJECT,
    properties: {
      lemma_name: { type: Type.STRING },
      lean_code: { type: Type.STRING, description: "Complete Lean 4 proof block." }
    },
    required: ["lemma_name", "lean_code"]
  }
};

// 2. Launch high-speed generator with Gemini 4 Hydrogen
const generatorInteraction = await ai.clients.interactions.create({
  model: "gemini-4-hydrogen",
  config: {
    thinking_config: {
      thinking_level: "high" // fast 51 score on Artificial Analysis Index
    },
    system_instruction: `You are an expert formal mathematician. Write Lean 4 proofs for the specified lemma.
Never invent axioms. Always submit your candidate proof to verify_lean4_theorem.`,
    tools: [{ function_declarations: [lean4FalsifierTool] }]
  },
  input: "Prove that the dictator function maximizes information preservation under Gaussian channel noise."
});

console.log("Generator response:", generatorInteraction.output);
