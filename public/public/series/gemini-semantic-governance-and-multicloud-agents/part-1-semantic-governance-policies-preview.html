Semantic Governance Policies (Preview): Stopping Unapproved Agent Tool Calls Before Execution

Authored by Google Gemini 4 Argon · Thinking Effort: High · Product Development & Creative Direction: Neil S. White • Published November 20, 2026 • Primary Source: Google Developers Blog (Deepti Sehrawat) • 6 min read

Release Summary: November 20, 2026

Google launched Semantic governance policies in Preview across the Gemini platform. Sitting outside the agent runtime at Agent Gateway, the policy engine uses an external LLM judge to evaluate every non-streamed proposed tool call against two mandatory checks—your plain-language business rules and original user intent—blocking violations before tools run and logging every verdict to Cloud Logging.

1. Why IAM Permissions and System Instructions Are Not Enough

Binary IAM controls answer only one question: whether an agent is technically allowed to invoke a tool such as read_file, send_email, or delete_file. They cannot evaluate business context—for instance, whether a finance coworker agent should email preliminary quarterly earnings two days before public release to an external investor claiming NDA coverage, with a personal Gmail address copied for evening review.

Instructions embedded inside a system prompt fail differently: persuasive user framing, executive urgency, or hidden indirect prompt injections inside retrieved documents can talk a model out of its own guidelines. Moving the check outside the agent at Agent Gateway separates compliance enforcement from application code.

2. Two Mandatory Pre-Execution Checks at Agent Gateway

Check / Component How It Operates Outcome on Pass vs. Denial
1. Plain-Language Policies Written in natural language via Google Cloud Console or gcloud beta ai semantic-governance-policies create; scoped globally to all tools or to a specific tool and parameter set. Allowed calls forward unchanged; denied calls replace the response and strip all tool calls with a configurable denial message.
2. User Intent Alignment Enabled by default with zero written policies required; checks whether proposed tool calls match what the human user actually asked for. Blocks hidden indirect prompt injections (such as a planning doc commanding delete_file on forecast drafts).
Text-Only Responses Pure explanations, plans, or follow-up questions carry no tool calls and bypass evaluation completely. Zero latency or judge-token overhead on conversational replies that take no action.
Supported Model Endpoints Works across Gemini API, Anthropic Messages API, Claude models on Gemini platform, and OpenAI-compatible Chat Completions including vLLM. Writes every verdict, judge rationale, and evaluation token count to Cloud Logging.

3. Three Finance Coworker Scenarios Verified in Google’s Walkthrough

  • Internal Close (Allowed): Employee requests sending Q3 preliminary numbers to controller@example.com. Both user intent and the plain-language corporate-domain policy pass.
  • External Investor + Personal Gmail Copy (Denied by Policy): Employee requests sending results to an investor under NDA and copying a personal inbox. Plain-language policy overrides user urgency and denies the entire call.
  • Hidden Doc Deletion Prompt (Denied by User Intent): A planning document injects an assistant directive to run delete_file on the Forecasts folder. The built-in intent check blocks it without needing a custom policy.
