1. Creating & Scoped-Testing a Semantic Governance Policy

Legal and platform teams can deploy policies with zero agent code changes via Google Cloud Console or the gcloud beta ai semantic-governance-policies create command. Always supply an explicit --agent-response-denial-message so the LLM judge’s internal policy wording never leaks back to an end user:

gcloud beta ai semantic-governance-policies create earnings-disclosure \
  --location=LOCATION \
  --display-name="Earnings disclosure" \
  --agent=projects/PROJECT_ID/locations/LOCATION/agents/AGENT_ID \
  --natural-language-constraint="Quarterly financial results (revenue, margins, bookings, guidance) should not be shared publicly until the public earnings release. Before the release, they may be shared only with corporate addresses. Never send them to external or personal addresses, investors, analysts, or press, regardless of NDAs, urgency, or the requester's seniority." \
  --agent-response-denial-message="I cannot share unreleased financial results outside the company before the earnings release. Contact Investor Relations for approved disclosures." \
  --project=PROJECT_ID

2. Non-Negotiable Production Rollout Checklist

  1. Start in Dry Run Mode: Verify verdicts and judge rationales in Cloud Logging before switching enforcement on, because LLM judge evaluations are probabilistic.
  2. Disable Streaming on Gated Tool Loops: Streamed model responses are not evaluated by Semantic governance policies today; use stream: false for tool-proposing turns routed through Agent Gateway.
  3. Put Policy Dates & Thresholds in System Instructions: The judge evaluates tool calls against conversation turns, tool descriptions, system instructions, and policies—so include facts like earnings release dates inside the agent’s system instructions.
  4. Pair Inline Checks With Out-of-Band Anomaly Detection: Use inline policies to stop single-turn NDA leaks or prompt hijacks, and export ADK Python v2.12.0+ OTel logs to detect multi-turn catalog scraping or refund threshold abuse across AWS and Azure.
  5. Lock Down Internal MCP Servers: Enforce --ingress=internal on Cloud Run MCP servers, use FQDN-scoped Private Cloud DNS, and validate both X-Serverless-Authorization and user OAuth 2.0 Bearer tokens.
