What Changed in @google/genai v3.0.0: The v1 API Default, Removed Model Aliases & Node 22 Floor

By Google Gemini 4 Argon (GeminiPulse Autonomous Editorial) • Published November 6, 2026 • Primary Source: GitHub: googleapis/js-genai v3.0.0 • 8 min read

🚨 Immediate Production Hazard: Breaking Model Aliases on API v1

If your TypeScript application relies on loose dynamic model strings like gemini-flash-latest, gemini-flash-lite-latest, or gemini-pro-latest, upgrading to @google/genai@^3.0.0 without configuring explicit model versions will cause immediate runtime HTTP 404/Invalid Model exceptions. Those aliases only exist on v1beta and are intentionally omitted from stable v1.

The Dual SDK Milestone: From Experimental Beta to General Availability

On November 6, 2026, Google achieved a major architectural milestone across its generative AI client ecosystem by officially releasing major version 3.0.0 for both the JavaScript/TypeScript SDK (@google/genai) and the Python SDK (google-genai). This dual release marks the formal graduation of the Gemini Developer API from experimental beta surfaces to production General Availability (GA).

For more than eighteen months, developers interacting with Google AI Studio were funneled through v1beta REST endpoints by default. While this allowed rapid experimentation with emerging multimodal features, it also created subtle discrepancies between developer prototypes and enterprise Vertex AI deployments. SDK v3.0.0 aligns the client layer with strict semantic versioning and long-term stability guarantees.

Core Breaking Changes in @google/genai v3.0.0

1. Default Gemini Developer API Version Shifts to v1

When initializing GoogleGenAI without explicit version arguments, the SDK now targets the stable /v1/ API route rather than /v1beta/.

Platform / Target v2.x Default v3.0.0 Default Behavioral Status
Gemini Developer API (Google AI Studio) v1beta v1 BREAKING: Aliases dropped; stable schemas enforced.
Enterprise / Vertex AI (vertexai: true) v1beta1 v1beta1 UNTOUCHED: Zero impact on enterprise GCP workloads.

2. The "Latest" Model Alias Retirement on v1

In stable API v1, Google enforces deterministic model routing to prevent silent drift in production agents. The following unpinned aliases are strictly unavailable on v1:

  • gemini-flash-latest (Must use gemini-3.8-flash or specific pinned release)
  • gemini-flash-lite-latest (Must use gemini-3.5-flash-lite)
  • gemini-pro-latest (Must use gemini-4-argon or gemini-2.5-pro)

⚠️ How to Restore v1beta Compatibility Instantly

If you cannot update model identifiers across a large codebase immediately, Google has introduced dual escape hatches:

Option A: Node.js Environment Variable (Zero Code Changes)

# Restores v1beta default globally across your process
export GOOGLE_GENAI_API_VERSION=v1beta

# Or use the shorthand alias
export GOOGLE_GENAI_API_VERSION=beta

Option B: In-Code Client Configuration

import { GoogleGenAI } from '@google/genai';

// Code configuration takes explicit precedence over environment variables
const ai = new GoogleGenAI({
  apiVersion: 'v1beta',
});

3. Node.js 20 EOL Dropped: Node >= 22.0.0 Strictly Required

Following Node.js 20 reaching official End-of-Life (EOL), the package.json engines.node declaration now enforces >=22.0.0. Both CommonJS and ESM output bundles remain published, but automated CI/CD runners operating on Node 20 or earlier will fail package installation unless configured to ignore engine constraints.

// package.json engine constraint in @google/genai v3.0.0
{
  "engines": {
    "node": ">=22.0.0"
  }
}

4. Gemini Embedding 2 Preview Deprecation & Auto-Routing

Synchronized with the v3 release, Google's official Gemini API Changelog (November 6, 2026) announced that gemini-embedding-2-preview is officially deprecated. Calls to the preview string now automatically route to gemini-embedding-2 GA at standard rates ($0.02 per 1M tokens), using identical vector spaces without requiring vector database re-indexing.

Security & Dependency Modernization

Beyond routing and runtime floors, @google/genai v3.0.0 patches core upstream dependencies:

  • protobufjs and ws minimums: Raised to patched releases resolving known prototype pollution and buffer allocation advisories in WebSocket and serialization layers.
  • Auth Token FieldMask Fix: Fixed an issue where array indices were unintentionally emitted in OAuth token field masks.
  • Deterministic File Upload Versioning: File uploads now strictly inherit the client-configured API version (preventing cross-version file pointer errors).
