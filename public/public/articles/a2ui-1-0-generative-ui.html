PART I · α CASTOR · DESIGN DIRECTOR, PRODUCT UX & SECURITY LENS α CASTOR · THE SIGNAL

Why Creative Directors and Security Teams Finally Agree on Generative UI

Solving the twin nightmares of ugly sandboxed iframes and walls of AI chat prose.

Anyone with a design eye—including the human creative director behind GeminiPulse—knows that raw Markdown chat bubbles are a terrible user interface for structured decisions. Ask an airline bot to rebook a delayed flight, and reading four paragraphs listing Seat 14A, Seat 17C, and baggage fees is exhausting compared to tapping an interactive seat card. Yet the first wave of "generative UI" workarounds swung to the opposite extreme: letting an LLM spit out raw HTML/Tailwind/JavaScript inside a sandboxed <iframe>.

In production software, raw-code iframes fail two fatal tests at once. Design leaders hate them because every generated card invents slightly wrong fonts, rogue border radii, broken mobile responsiveness, and jarring accessibility regressions. Security engineers block them because executing LLM-synthesized scripts near authenticated customer sessions is an XSS and data-exfiltration minefield.

On November 11, 2026, Google’s A2UI 1.0 GA (Agent-to-User Interface) resolved that standoff cleanly—and released it as an open, vendor-neutral protocol compatible day-zero with MCP Apps, Claude, and Gemini. Instead of writing HTML or Swift code, the agent streams a compact, declarative JSON blueprint referencing your registered component catalog (FlightSeatCard, ExpenseApprovalRow, BudgetSlider). Native open-source renderers compile that blueprint directly into real React, Angular, Lit, Flutter, SwiftUI, or Jetpack Compose views inheriting your exact brand tokens and screen-reader semantics.

Two quiet breakthroughs make 1.0 enterprise-ready: A2UI Express shrinks layout token overhead by up to 64% so interactive screens stream in sub-second time, and Secure Data-Binding lets the agent bind a component to a client/server state pointer ($data.account.availableBalance) without the sensitive dollar figure or customer SSN ever entering the AI model’s context window.

“Let the AI decide which components belong on screen for this moment; let your human-crafted design system govern every pixel, font curve, and security boundary.”

CHAPTER 02 / 04 · WHAT THIS MEANS FOR YOU ADAPTIVE READER QUESTIONS
FOR CREATIVE DIRECTORS & DESIGN SYSTEMS

Does adopting A2UI mean surrendering visual art direction to an AI model?

The exact opposite. Your design team defines the approved catalog—your typography, spacing rules, dark/light tokens, and motion curves—and the agent can only compose screens out of those vetted building blocks using scoped catalogIds.

FOR CROSS-PLATFORM PRODUCT TEAMS

Do we have to write separate agent prompts for our React web app, iOS app, and Android app?

No. One A2UI JSON blueprint from your TypeScript, Python, or Dart backend compiles natively through the React renderer on web, the SwiftUI renderer on iPhone, and Jetpack Compose on Android.

ECOSYSTEM LOCK-IN CHECK

Is A2UI locked exclusively to Gemini models?

No. Google open-sourced A2UI 1.0 as a model-agnostic specification with day-zero interoperability across Model Context Protocol (MCP) Apps, Claude, and Gemini.

Wiring Scoped Catalogs, Opaque Data Pointers & Bidirectional RPC

How callRendererFunction and callAgentFunction eliminate full-screen re-renders.

In pre-1.0 agent UI prototypes, clicking a button or validating a form field required round-tripping the entire screen state back through an LLM turn—adding 1.5 seconds of lag just to check a date range. A2UI 1.0 introduces typed Bidirectional RPC messages: callRendererFunction lets the agent invoke deterministic client-side helpers (local sorting, currency formatting, instant field validation), while callAgentFunction fires structured user intent payloads (approve_invoice, recalculate_tier) straight back into an active @google/genai Interactions session.

Notice how Secure Data-Binding changes compliance reviews in healthcare, fintech, and HR software: the agent emits { "component": "MetricReadout", "bind": "$vault/customer/netWorth" }. Because the host renderer resolves $vault/* pointers against your authenticated client store at render time, the LLM orchestrates the exact right visual layout while remaining mathematically blind to the underlying PII.

Enable A2UI Express encoding on streaming responses with gemini-4-hydrogen: cutting layout token count by up to 64% directly reduces output token cost ($7.50/1M) by nearly two-thirds while painting the first interactive card in under 350 milliseconds.

01 · Keep Sensitive State Behind $vault Bindings
Pass schema keys—not raw customer balances, health records, or tokens—into model context, and resolve values inside your native A2UI renderer.
02 · Namespace Component Libraries with catalogIds
Scope core design primitives (ui.core.v1) separately from domain widgets (billing.approvals.v1) so multi-agent screens compose cleanly.
03 · Enable A2UI Express on High-Traffic Streams
Express intermediate token compression cuts layout serialization overhead by up to 64%, improving both TTFB and output token spend.
COMPLETE @GOOGLE/GENAI v3.3.0 + A2UI 1.0 · PRIVACY-PRESERVING APPROVAL BLUEPRINT 
import { GoogleGenAI, Type } from "@google/genai";

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

// Scoped component catalog manifest exposed to Gemini (zero raw HTML/JS allowed)
const REGISTERED_CATALOG = {
  catalogId: "agile.finance.v1",
  components: ["ApprovalCard", "VarianceBarChart", "ActionRow"],
  rpcHandlers: ["callAgentFunction:submitApproval", "callRendererFunction:validateCap"],
};

export async function generateNativeApprovalScreen({ requestSummary }) {
  const interaction = await ai.interactions.create({
    model: "gemini-4-hydrogen",
    input: `Compose an A2UI 1.0 screen using catalog ${REGISTERED_CATALOG.catalogId} for:\n${requestSummary}\nBind private balances via $vault pointers only.`,
    config: {
      thinking_config: { thinking_level: "low" },
      response_mime_type: "application/json",
      response_schema: {
        type: Type.OBJECT,
        properties: {
          a2uiVersion: { type: Type.STRING },
          catalogId: { type: Type.STRING },
          encoding: { type: Type.STRING },
          root: {
            type: Type.OBJECT,
            properties: {
              component: { type: Type.STRING },
              title: { type: Type.STRING },
              dataBinding: { type: Type.STRING }, // e.g. "$vault/dept/remainingBudget"
              onApproveRpc: { type: Type.STRING }, // e.g. "callAgentFunction:submitApproval"
            },
            required: ["component", "title", "dataBinding", "onApproveRpc"],
          },
        },
        required: ["a2uiVersion", "catalogId", "encoding", "root"],
      },
    },
  });

  return JSON.parse(interaction.output_text);
}
