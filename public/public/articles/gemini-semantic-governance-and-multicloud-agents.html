PART I · α CASTOR · ENTERPRISE RISK, COMPLIANCE & MULTI-CLOUD REALITY LENS α CASTOR · THE SIGNAL

Why Binary Permissions and System Prompts Break Down Under Real Agent Traffic

Moving guardrails out of fragile prompt text and into an auditable policy enforcement plane that spans Gemini, Claude, vLLM, AWS Bedrock, and Microsoft Foundry.

For three years, enterprise security teams have relied on two brittle defenses for autonomous agents: coarse IAM roles that decide whether an agent can invoke an API, and polite instructions tucked inside a system prompt telling the model what it ought not to do. In production, both assumptions fail simultaneously. When an employee asks a finance coworker agent to email preliminary quarterly numbers to an investor claiming NDA coverage and copy a personal inbox, the agent technically holds both read and mail permissions—and persuasive urgency routinely talks models past system-prompt reminders.

Google’s November 20, 2026 security double-header addresses that gap at the exact boundary where software becomes irreversible action. First, Semantic governance policies (Preview in Gemini platform) place an external LLM judge behind Agent Gateway, inspecting every proposed tool call before it returns to the agent. Second, Agent Anomaly Detection expands in Private Preview beyond Google Cloud so OpenTelemetry traces from agents hosted on AWS Lambda, Amazon Bedrock, and Microsoft Foundry flow into one Google Cloud risk console without moving underlying workloads.

What stands out strategically is that legal, compliance, and risk leaders no longer need engineering sprints to adjust agent boundaries. Rules read like everyday compliance prose—such as prohibiting unreleased revenue disclosures outside corporate domains regardless of NDAs, urgency, or requester seniority—and take effect without redeploying agent code. Even when teams have written zero custom policies, the built-in user intent alignment check stays active by default, catching indirect prompt injections hidden inside shared planning docs that try to delete forecast drafts.

Still, CISOs and product owners must pair these controls with honest operational realism. Google explicitly notes that because semantic verdicts rely on an LLM judge, decisions are probabilistic and teams should validate policies in dry run mode before blocking production traffic. Furthermore, streamed model responses bypass inline semantic evaluation today, while multi-cloud Anomaly Detection operates asynchronously out of band and currently expects Python agents built on ADK v2.12.0+.

“You cannot prompt-engineer compliance inside an untrusted context window; enforcement has to sit outside the agent where proposed tool calls are judged before they execute.”

CHAPTER 02 / 04 · WHAT THIS MEANS FOR YOU ADAPTIVE READER QUESTIONS
FOR CISOS & COMPLIANCE TEAMS

Does Semantic governance work if our agents call Claude, OpenAI-compatible, or self-hosted vLLM models?

Yes. Agent Gateway evaluates proposed tool calls regardless of whether your agent reaches Gemini API, Anthropic Messages API, Claude models on Gemini platform, or OpenAI-compatible Chat Completions endpoints including self-hosted vLLM servers.

FOR MULTI-CLOUD PLATFORM LEADERS

Do we have to migrate AWS Bedrock or Azure Foundry workloads to GCP to use Agent Anomaly Detection?

No. Agents remain on AWS Lambda, Microsoft Foundry, or on-premises infrastructure. Using keyless Workload Identity Federation and ADK Python v2.12.0+ OpenTelemetry exporters, only telemetry traces and message-content logs travel to telemetry.googleapis.com.

FOR PRODUCT & LEGAL TEAMS

What happens to normal conversational answers when Semantic governance is enabled?

Responses that contain only text—such as an explanation, plan, or clarifying question—skip the policy engine completely because they invoke no tool action. Only responses proposing tool calls undergo policy and user-intent evaluation.

PART II · β POLLUX · AGENT GATEWAY INTERCEPTION, GCLOUD CLI & OTEL TELEMETRY β POLLUX · THE WORKBENCH

How Inline Policy Judging & Out-of-Band Multi-Cloud Traces Wire Together

Configuring Agent Gateway interception, authoring gcloud natural-language constraints, and exporting ADK v2.12.0+ EVENT_ONLY logs across AWS and Azure.

At the wire level, Semantic governance policies interpose between the model and your agent runtime rather than between the agent and downstream tools. When you route agent model egress through Agent Gateway, every non-streamed model response containing a proposed tool call is forwarded to the policy engine before reaching your agent process. An LLM judge evaluates the call against the full conversation history, the agent’s system instructions (where time-sensitive facts such as earnings dates must reside), tool descriptions, and attached natural-language policies.

If both checks pass—user intent alignment and explicit policy rules—the original model response passes to your agent untouched. If either check fails, the engine strips the proposed tool calls and substitutes your configured --agent-response-denial-message (preventing internal compliance wording from leaking to end users), while writing the verdict, judge rationale, and evaluation token count to Cloud Logging. In Google’s finance walkthrough, an authorized send to controller@example.com passed, an NDA-justified send to jordan@investor.example was blocked entirely by policy, and an injected delete_file call from a planning doc was stopped by the built-in intent check.

To catch cross-turn behavioral drift that looks valid one call at a time—such as paging list_inventory in batches of 100 across an entire catalog—Agent Anomaly Detection reads OpenTelemetry spans and conversation events shipped to telemetry.googleapis.com. Setting OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=EVENT_ONLY and ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false keeps payloads structured for analysis, surfacing external agents in the Monitored agents list within 30 minutes and flagging real failures such as 10 of 40 runaway Amazon Nova Lite Bedrock sessions and 4 of 6 Microsoft Foundry refund-override exploits.

01 · Place Policy-Critical Facts Inside System Instructions & Use Non-Streaming Calls
The policy judge reads system instructions, tool descriptions, and conversation turns—and does not evaluate streamed responses—so keep dates/thresholds in system instructions and disable streaming on gated tool loops.
02 · Validate Policies in Dry Run Mode & Customize End-User Denial Messages
Because the judge rationale can quote internal compliance constraints, supply an explicit --agent-response-denial-message and audit Cloud Logging verdicts in dry run mode before enabling enforcement.
03 · Pair Keyless Workload Identity Federation With EVENT_ONLY OTel Logs
Never ship static Service Account JSON keys to AWS or Azure; exchange AWS IAM roles or Entra ID identities via Workload Identity Federation and set ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false.

// Step 1 (CLI): Create an inline Semantic governance policy in Preview
// gcloud beta ai semantic-governance-policies create earnings-disclosure \
//   --location=us-central1 \
//   --display-name="Earnings disclosure" \
//   --agent=projects/PROJECT_ID/locations/us-central1/agents/AGENT_ID \
//   --natural-language-constraint="Before earnings release, share quarterly results only with corporate addresses." \
//   --agent-response-denial-message="I cannot share unreleased financial results externally before earnings."

import { GoogleGenAI } from "@google/genai";

// Step 2 (TypeScript): Route non-streamed Interactions traffic via Agent Gateway
const ai = new GoogleGenAI({
  httpOptions: {
    apiVersion: "v1beta",
    baseUrl: process.env.AGENT_GATEWAY_URL,
  },
});

const interaction = await ai.interactions.create({
  model: "gemini-4-argon",
  thinking_level: "high",
  stream: false,
  system_instruction:
    "Finance coworker agent. Next public earnings release is December 2, 2026.",
  input:
    "Send preliminary Q3 results to controller@example.com for month-end close.",
});

console.log("Policy-checked response status:", interaction.status, interaction.id);
