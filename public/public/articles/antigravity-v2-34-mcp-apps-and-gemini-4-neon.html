Why Reusable MCP App Surfaces Replace Fragile Tab Switching

Giving teams persistent side-panel release boards, sidebar consoles, and domain file editors without forcing every user out of their coding or operations workspace.

Modern engineering and product teams rarely get stuck because an LLM cannot write another paragraph of summary text. They get stuck on the last ten percent of operational handoffs: verifying which canary percentage is live before clicking promote, inspecting a proprietary geometry or topology file that raw text cannot render, or comparing deployment checklists across tabs while an agent edits code nearby.

Antigravity previously solved one-off visualization inside a single thread with /generative_ui, which excels at disposable diagrams or quick interactive calculators. Yet teams building durable developer tools, incident responders, and internal plugins need views backed by live authentication, persistent plugin APIs, and repeatable controls that survive outside a single prompt.

In Google Antigravity v2.34.0 (released November 20, 2026), MCP Apps bridge that divide cleanly. By supporting the open io.modelcontextprotocol/ui standard alongside Antigravity entrypoints (com.google.antigravity/ui), one plugin can render an inline card inside chat, dock a live board in the side panel beside your conversation, occupy a full-width screen under Plugins in the left sidebar, or replace the built-in viewer whenever a team opens custom file extensions.

For engineering managers and plugin authors, the rollout comes with two practical wins and one clear boundary. First, Gemini 4 Neon and Orchestrator (Neon) now reach paid consumer plans, Gemini API keys, and Application Default Credentials, while new Clerk, Docusign, and TestMu AI plugins land in the Marketplace alongside Cmd+E terminal side questions and cleaner single-column diff gutters. Second, because Antigravity CLI and IDE extensions do not mount ui:// iframes, every plugin must still return crystal-clear plain-text responses so terminal automation never breaks.

“One MCP plugin can now render a live canary board in the Antigravity side panel for humans while serving clean plain-text tool results to headless CLI pipelines.”

FOR PRODUCT & PLATFORM LEADERS

When should a team build an MCP App instead of relying on /generative_ui?

Use MCP Apps whenever the interface needs live MCP server calls, Marketplace distribution, side-panel or full-page placement, or custom file-extension editing. Keep /generative_ui for one-off charts and exploratory prototypes inside one chat.

FOR ENTERPRISE & API KEY DEVELOPERS

Who gains Gemini 4 Neon and Orchestrator access in Antigravity v2.34.0?

Antigravity v2.34.0 brings Gemini 4 Neon and Orchestrator (Neon) to eligible paid consumer plans, Gemini API key users, and Application Default Credentials (ADC), alongside Enterprise support.

FOR PLUGIN & SECURITY TEAMS

Can a custom file-viewer plugin read arbitrary files on a developer laptop?

No. File-viewer tools are unconditionally hidden from the LLM in the desktop app, never receive raw host filesystem paths, and read/write only the exact opaque antigravity-file:// URI opened by the user up to 10 MiB.

How com.google.antigravity/ui, Opaque File URIs & Host Limits Work Under the Hood

Negotiating MCP initialize capabilities, scaffolding with /mcp-app-development, respecting 1 MiB trajectory budgets, and preserving agy CLI parity.

At session startup during MCP initialize, the Antigravity desktop App (v2.34.0+) advertises both capabilities.extensions["io.modelcontextprotocol/ui"] and com.google.antigravity/ui with {"entrypoints": ["aux_pane", "global", "file"]}. Each tool links to a bundled single-file HTML document (text/html;profile=mcp-app) via _meta.ui.resourceUri, and tools adding aux_pane or global entrypoints automatically suppress inline chat rendering so views do not duplicate across panes.

Custom file viewers require strict separation onto their own tool. Any tool declaring a file entrypoint (with lowercase dot-prefixed extensions, where the first enabled server claiming an extension wins) is hidden from the model regardless of visibility and invoked by the host with {"file": {"name", "resourceUri"}} carrying an opaque antigravity-file://<uuid>/<name> identifier. The iframe reads bytes via resources/read (base64 application/octet-stream, max 10 MiB) directly from Antigravity without hitting the MCP server, and writes local edits only when hostContext["com.google.antigravity/resources"]?.write is present via com.google.antigravity/resources/write.

Production plugin authors must engineer around four hard host budgets and two CLI quirks. Antigravity enforces a 10 MiB cap on ui:// HTML and files, a 1 MiB cap on persisted CallToolResult step payloads, at most 4 concurrent tools/call calls per view (aborted on close), and an LRU cache of 5 hidden background frames. Because iframes run under default-deny CSP with zero persistent storage and Antigravity sends no ui/resource-teardown event on close, views must persist state eagerly. Finally, agy CLI ignores _meta.ui.visibility and mounts no iframes, so every tool must always return clean plain-text content alongside structuredContent.

01 · Isolate file Entrypoints & Gate Saves on hostContext Write Capability
Keep custom file viewers on a separate tool so LLM invocation never collides with host-only {"file": {"name", "resourceUri"}} payloads, and check hostContext["com.google.antigravity/resources"]?.write before calling resources/write.
02 · Keep Persisted CallToolResult Payloads Under 1 MiB & Persist Eagerly
Load large tables lazily through app-only tools/call requests instead of bloated step outputs, keep ui:// HTML under 10 MiB, and never wait for ui/resource-teardown before saving user edits.
03 · Return Plain-Text content & Validate Strictly for agy CLI Parity
Because Antigravity CLI exposes all tools without ui:// iframes and ignores visibility filters, always populate human-readable content alongside structuredContent and verify bundles with agy plugin validate <path> --strict.

Argon’s Bottom Line: MCP Plugins Are Growing Real Workspaces Inside Antigravity

By pairing standard io.modelcontextprotocol/ui iframes with side-panel, full-page, and opaque file-viewer entrypoints, Antigravity v2.34.0 turns plain-text tools into full interactive developer surfaces without breaking CLI automation.

Why this matters today: plugin builders no longer have to choose between terminal portability and visual polish. Shipping a single ui:// HTML resource alongside clean plain-text content gives Antigravity App users persistent side-panel boards and file editors while agy CLI workflows continue running untouched.
